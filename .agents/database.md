# Database

- **Database Safety**: Always perform a database backup (e.g. running `/usr/local/sbin/kuing-db-backup` or creating a timestamped dump) before executing any direct database operations, batch updates, or migrations on the live database.
- **Full Backup Before Partial**: Always take a full database backup (all tables) before taking any partial/selective backup. Never rely on a partial backup as the sole safety net.
- **Confirm Before Overwrite**: Always explicitly confirm with the user before overwriting any existing database table or data. Show clearly which tables/rows will be affected and get user approval before proceeding.
- **Never Assume Tables Are Unchanged**: Never assume a table is still in the same state as when the last backup was taken. Always compare the current live table against the backup before performing any restore or overwrite — changes (user edits, new rows, updates) may have occurred since the backup.
- **Per-style template variables live in the DB, not git**: `{TOKEN}` substitutions in `template/default/common/*.css` are resolved from `pre_common_stylevar` (`styleid`, `variable`, `substitute`) at CSS-compile time. The `variable` column stores **lowercase** names (`fontsize`, `font`, …) while templates reference them uppercase (`{FONTSIZE}`); the lookup is case-insensitive. Current values: style 1 `fontsize=1.05em/1.5`, style 3 `fontsize=16px/1.5`, style 4 `fontsize=12px/1.5` (blog aligned to x5 on 2026-09-26). Because these are DB rows, **they are invisible to version control** — a repo clone or DB restore silently reverts them, so record any change here and rebuild styles afterwards.
- **Table names**: style tables are `pre_common_style` and `pre_common_stylevar`; there is no `pre_style` (Discuz's own `%t` substitution does not add the prefix here, so use literal qualified names). The config key is `dbpw`, not `dbpass`. Query via a `mysql --defaults-extra-file` created with `umask 077` so the password never reaches a command line — and redact on `dbpw`, `dbpass`, `requirepass`.
- **After changing a style variable**: run `.agents/tools/rebuild_styles.php` to recompile, then confirm the value landed in `data/cache/style_{id}_*.css`. The DB edit alone changes nothing visible.

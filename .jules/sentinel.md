## 2026-08-01 - Pre-insert HTML Escaping for Discuz! Post Comments
**Vulnerability:** Stored Cross-Site Scripting (XSS) in reply-to-comment conversion (`source/app/forum/extend/extend_thread_comment.php`).
**Learning:** In Discuz! architecture, `table_forum_postcomment::t()->format_postcomment()` does not HTML-escape comments when formatting them for display (`viewthread`, `commentmore`, `space`). Discuz! assumes that all text stored in `pre_forum_postcomment` has already been passed through `dhtmlspecialchars()` and `censor()` before insertion. When `extend_thread_comment.php` was added to convert replies into comments on reply posts (`allowpostcomment == 2`), it extracted `$parameters['message']` via `messagecutstr()` without HTML entity escaping, leaving raw tags like `<script>` in the database.
**Prevention:** Whenever creating or updating `forum_postcomment` rows in Discuz! plugins or extension classes, always pre-escape input using `censor(trim(dhtmlspecialchars(...)), '***')` before calling `table_forum_postcomment::t()->insert()`.

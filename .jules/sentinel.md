## 2026-08-01 - Pre-insert HTML Escaping and Column Overflow Protection for Discuz! Post Comments
**Vulnerability:** Stored Cross-Site Scripting (XSS) and database column overflow in reply-to-comment conversion (`source/app/forum/extend/extend_thread_comment.php`).
**Learning:** In Discuz! architecture, `table_forum_postcomment::t()->format_postcomment()` does not HTML-escape comments when formatting them for display (`viewthread`, `commentmore`, `space`). Discuz! assumes that all text stored in `pre_forum_postcomment` has already been passed through `dhtmlspecialchars()` and `censor()` before insertion. When `extend_thread_comment.php` was added to convert replies into comments on reply posts (`allowpostcomment == 2`), it extracted `$parameters['message']` via `messagecutstr(..., 200)` without HTML entity escaping, leaving raw tags like `<script>` in the database. Additionally, because `messagecutstr(..., 200)` runs before HTML entity encoding, a 200-character message of `<`, `>`, `"`, or `&` can expand up to 1000–1200 characters after escaping, overflowing `pre_forum_postcomment.comment` (VARCHAR(255)).
**Prevention:** Whenever creating or updating `forum_postcomment` rows in Discuz! plugins or extension classes, always pre-escape input using `censor(trim(dhtmlspecialchars(...)), '***')` before calling `table_forum_postcomment::t()->insert()`. Furthermore, impose a safe post-encoding length check (`strlen($postcomment) > 255`) and decline to create the derived comment (`''`) when the escaped value exceeds the column limit.

# Bolt's Journal

## 2026-08-01 - No PHP CLI in sandbox, but a real PHP interpreter is reachable via npm
**Learning:** This repo is pure PHP (Discuz! X) with no `package.json`/pnpm and no local `php` binary, `phpunit`, or linter installed. `apt-get install php-cli` fails (no matching package name on this image) and network access to `deb.debian.org` / GitHub release-asset CDNs (`release-assets.githubusercontent.com`, `objects.githubusercontent.com`) is blocked via TLS (`SSL_ERROR_SYSCALL`), so downloading a static PHP binary directly usually fails. However, `codeload.github.com` and the `registry.npmjs.org` are reachable, and `npm install @php-wasm/cli` pulls down a genuine PHP 8.5 CLI (WASM-based, runs via Node) that supports `php-wasm-cli -l file.php` for syntax checks and can execute arbitrary PHP scripts (including `require`-ing real project files) for correctness/perf testing. This is the way to actually verify PHP changes in this sandbox instead of guessing from a Python reimplementation.
**Action:** When touching PHP logic in this repo and no local `php` is available, run `npm install @php-wasm/cli` in a scratch dir (e.g. `/tmp/phpwasm`) and use `node_modules/.bin/php-wasm-cli -l <file>` for lint and `node_modules/.bin/php-wasm-cli <script.php>` to execute fuzz/correctness/benchmark harnesses against the real source files before opening a PR. Don't waste time retrying apt or GitHub release-asset downloads for a PHP binary — they're blocked in this environment.
